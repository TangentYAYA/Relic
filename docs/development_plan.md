# Relic 阶段开发计划

本计划遵循小步实现、每阶段测试、真实数据优先的原则。当前阶段只完成架构和环境验证，不实现业务功能或完整 UI。

## 阶段 1：架构设计与技术验证（已完成）

- 完成分层、依赖、数据结构、任务接口和异常边界设计。
- 验证 Python、PySide6、pytest 和 TSK CLI。
- 固定 CLI 4.14.0 与 pytsk3 4.15.0 的版本差异记录。
- 验收：六份 docs 文件存在，环境报告不夸大 TSK 验证范围。

## 阶段 2a：PySide6 UI 外壳（已完成）

- 完成十个页面、统一 Dark Forensics 主题、导航和 Qt Model/View 原型。
- 明确标记 Mock 演示状态，不连接 TSK、不读取证据、不写入案件数据。
- 验收：应用可启动，十个页面可切换，表格可选择/排序，文件系统页为三栏布局。

## 阶段 3a：案件、证据与哈希（已完成）

- 已实现案件 JSON 持久化、案件目录隔离、案件生命周期和证据元数据。
- 已实现通过 TSKAdapter 调用真实 `mmls`/`fsstat`、RAW 路径只读访问和 4 MiB 流式 SHA-256。
- 哈希通过 QThreadPool 在后台运行，结果和关键操作写入案件根目录审计 JSONL。
- 验收：`tests/test_case_evidence.py` 的 6 项测试通过；真实 MBR 分区可由 TSK 解析。

## 阶段 4a：文件系统浏览与导出（当前）

- 使用经过实际验证的 `fls -m` mactime 输出增量解析文件清单。
- 使用 `istat` 保留原始元数据，使用 `icat` 流式导出到案件 exports 目录。
- 保存 JSONL 清单、导出记录、导出哈希和审计事件。
- 验收：已知 FAT 测试镜像验证文件名、目录 inode、大小、元数据、导出内容、哈希和错误路径。

## 阶段 5a：基础文件分析（当前）

- 新增独立 `AnalysisService` 和统一 `AnalysisResult`。
- 完成内容签名、扩展名异常、纯文本关键词、Pillow EXIF、案件缩略图和文件标记。
- 分析结果、标记和审计记录均写入案件目录；UI 只负责触发和展示。
- 验收：`tests/test_analysis_service.py` 覆盖已知样本、空 EXIF、二进制跳过和错误路径。

## 阶段 6a：统一分析任务与时间线（当前）

- 新增独立 `AnalysisTaskEngine`，现有分析模块通过 handler 注册，不搬迁分析逻辑。
- 新增 `TimelineService`，区分文件系统时间和软件审计时间，统一使用 UTC。
- 任务中心支持历史、进度和取消；时间线页面支持刷新、类型筛选和事件详情。
- 验收：`tests/test_task_engine_timeline.py` 覆盖任务状态、错误、取消、多任务和时间线筛选。

## 阶段 7a：审计与证据完整性（当前）

- 固定审计规范化字段顺序、UTF-8 编码和 genesis 前置值。
- 实现链验证、sequence/previous_hash/内容检查和独立 checkpoint。
- 实现证据结束 SHA-256 复核、完整性摘要和自动化质量检查。
- 完整性中心显示证据哈希、导出哈希、审计链、检查点和质量检查。
- 验收：审计副本篡改测试通过，且测试不修改真实案件审计记录。

## 阶段 8a：Markdown 取证报告（当前）

- 新增独立 `ReportService`，从案件真实 JSON/JSONL、时间线和完整性服务读取数据。
- 生成案件 `reports` 目录内的 Markdown，提供源码和 Qt 预览，不生成 HTML。
- 缺失信息显示为未完成/未提供，报告生成动作写入审计日志。
- 验收：使用测试案件逐项核对报告字段、哈希一致性、审计动作和 Markdown 输出。

## 阶段 2：项目骨架与基础设施

- 建立 `relic/` 包、配置、领域模型和依赖反转接口。
- 实现 JSON 原子仓储、JSONL 单 writer、日志初始化和 TSK 启动诊断。
- 验收：空案件可创建并恢复；基础单元测试通过。

## 阶段 3：案件、证据与哈希

- 实现案件生命周期、RAW 证据注册、路径隔离和 4 MiB 流式 SHA-256。
- 实现基线和结束复核，记录审计事件。
- 验收：大文件流式测试、路径异常测试、哈希篡改测试通过。

## 阶段 4：TSKAdapter 与分区/文件系统

- 先用实际 `mmls/fsstat` 输出建立解析 fixture，再实现命令适配器。
- 实现分区选择、sector offset 传递、文件系统识别和错误诊断。
- 验收：真实授权镜像和受控错误镜像通过；不支持情形明确显示。

## 阶段 5：文件清单与文件系统工作区

- 实现 `fls` 增量 JSONL、`istat` 详情和 Qt Model/View 三栏布局。
- 后台任务显示进度、状态和取消。
- 验收：大清单不阻塞 GUI，清单可重启恢复。

## 阶段 6：内容分析

- 按独立任务实现签名识别、扩展名异常、纯文本关键词、支持范围内 EXIF、缩略图、标记和备注。
- 未实现格式返回 unknown/unsupported，不以猜测代替结果。
- 验收：fixture corpus、误报边界、取消和错误路径通过。

## 阶段 7：时间线、导出与审计完整性

- 实现时间线统一模型、`icat` 流式导出、导出哈希、审计哈希链和 checkpoint。
- 验收：源到导出可追溯，链篡改和尾截断可检测。

## 阶段 8：质量检查与报告

- 实现自动化质量检查和 Markdown 报告。
- 报告只读取真实仓储结果，输出完整性结论和限制说明。
- 验收：未完成项为 incomplete/warning，不伪造 pass。

## 阶段 9：整合 UI、打包和回归

- 已完成十个页面的交互、设置入口和错误提示烟测。
- 已使用 PyInstaller 6.22.3 打包，并验证 EXE 首次启动；TSK 仍通过外部目录配置。
- 已完成全套 pytest、异常矩阵、安全静态检查、性能实测和 UI 导航烟测。
- 限制：提供的 EWF 分卷检材尚未接入 EWF 解码；不计为 RAW 完整检材成功验收。

## 每阶段固定交付

1. 变更说明和设计决策。
2. 相关测试及实际输出。
3. README/进度文档同步更新。
4. 未解决风险和下一阶段入口。

任何阶段都不得删除既有断言、伪造分析结果、把 UI 事件回调变成业务层，或声称软件级只读等同硬件写保护。
